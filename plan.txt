Detailed fix plan: EditorPanel not opening

Project area involved
- Arya/client/src/components/ProjectPreview.tsx
- Arya/client/src/components/EditorPanel.tsx
- Arya/client/src/pages/Projects.tsx
- Arya/client/src/assets/assets.ts

1. Problem I found

The main issue was not inside EditorPanel alone.
The real problem was that EditorPanel and ProjectPreview were not fully connected through the page that renders them.

What was already present:
- ProjectPreview was injecting iframeScript into the preview HTML.
- iframeScript was listening for clicks inside the iframe.
- iframeScript was sending window.parent.postMessage with type "ELEMENT_SELECTED".

What was missing:
- No parent component was listening to those messages.
- No page state was storing the selected element.
- EditorPanel was not mounted inside the page next to ProjectPreview.
- There was no callback path for EditorPanel changes to go back into the iframe.

Because of that, clicking the preview could highlight an element inside the iframe script, but React never received that information, so the panel never opened.

2. How I traced it

Step 1:
I opened ProjectPreview.tsx and checked whether it had any code for:
- opening EditorPanel
- sending selected element data to parent
- exposing methods to update the iframe

Result:
- It only injected iframeScript.
- It did not listen for postMessage events from the iframe.
- It did not pass any selection data out.

Step 2:
I opened EditorPanel.tsx and checked whether:
- the component was valid
- the component was imported somewhere
- it had any obvious runtime problems

Result:
- It had UI and handlers, but it was a standalone component.
- It had a missing X icon import from lucide-react.
- It was not enough by itself because nothing was rendering it from the page.

Step 3:
I searched the project for where ProjectPreview and EditorPanel were used.

Result:
- ProjectPreview was rendered in Projects.tsx.
- EditorPanel was not wired into that page flow.

Step 4:
I checked the iframeScript source in assets.ts.

Result:
- The script was already doing the selection work correctly.
- It posted messages with:
  - ELEMENT_SELECTED
  - CLEAR_SELECTION
- It also listened for:
  - UPDATE_ELEMENT
  - CLEAR_SELECTION_REQUEST

That meant the iframe side of the feature was mostly ready. The missing part was the React connection layer.

3. The fix strategy

I used Projects.tsx as the coordinator between the two components.

Why:
- Projects.tsx already renders the preview.
- It is the correct place to hold shared state.
- It can pass selection data down into EditorPanel.
- It can use a ref to call functions on ProjectPreview.

Final data flow after the fix:
- User clicks an element inside the iframe preview
- iframeScript sends ELEMENT_SELECTED to the parent window
- ProjectPreview catches that message
- ProjectPreview calls onElementSelect(...)
- Projects.tsx stores the selected element in React state
- EditorPanel receives that state and becomes visible
- User edits fields in EditorPanel
- Projects.tsx receives the update
- Projects.tsx calls previewRef.current.updateSelectedElement(...)
- ProjectPreview posts UPDATE_ELEMENT back into the iframe
- iframeScript applies the changes to the selected DOM element

4. Changes I made in each file

File: Arya/client/src/pages/Projects.tsx

Purpose:
This file became the bridge between preview and editor.

Changes made:
- Imported EditorPanel.
- Imported the shared SelectedElementData type.
- Added selectedElement state:
  const [selectedElement, setSelectedElement] = useState<SelectedElementData | null>(null)
- Kept using previewRef, but extended its use so it can send updates and clear selection.
- Added handleElementUpdate():
  - merges incoming editor updates with current selectedElement state
  - updates React state so the panel always shows the latest values
  - calls previewRef.current?.updateSelectedElement(updates)
- Added handleEditorClose():
  - clears selectedElement state
  - tells the iframe to remove the highlight with clearSelection()
- Updated the JSX:
  - passed onElementSelect={setSelectedElement} to ProjectPreview
  - passed onClearSelection={() => setSelectedElement(null)} to ProjectPreview
  - rendered EditorPanel beside ProjectPreview

Why this solved it:
- Now there is actual React state controlling whether the panel appears.
- When selectedElement is null, EditorPanel returns null.
- When selectedElement gets data from the iframe, EditorPanel renders.

File: Arya/client/src/components/ProjectPreview.tsx

Purpose:
This file became responsible for communication between iframe and React parent state.

Changes made:
- Imported useEffect and useImperativeHandle.
- Imported SelectedElementData type.
- Updated device prop type from:
  'desktop' | 'mobile' | 'tablet'
  to:
  'desktop' | 'phone' | 'tablet'

Why this mattered:
- Projects.tsx was using 'phone'.
- ProjectPreview expected 'mobile'.
- The width map used phone/tablet/desktop keys.
- This mismatch could break the selected device layout logic.

More changes:
- Added two optional props:
  - onElementSelect?: (element) => void
  - onClearSelection?: () => void

- Extended the forwarded ref interface with:
  - updateSelectedElement(...)
  - clearSelection()

- Added useImperativeHandle so parent components can call methods on the iframe:
  - getCode() returns current srcDoc
  - updateSelectedElement() posts UPDATE_ELEMENT into iframe
  - clearSelection() posts CLEAR_SELECTION_REQUEST into iframe

- Added a useEffect message listener on window:
  - checks if the message came from the current iframe
  - if type is ELEMENT_SELECTED, forwards payload through onElementSelect
  - if type is CLEAR_SELECTION, calls onClearSelection

- Added title="Project preview" to iframe

Why this solved it:
- ProjectPreview now listens to the iframe's postMessage events.
- It passes selection data upward into React state.
- It also gives the parent a way to push updates back into the iframe.

File: Arya/client/src/components/EditorPanel.tsx

Purpose:
This file needed to be made reliable and typed cleanly so it could render and update correctly.

Changes made:
- Added:
  import { X } from 'lucide-react';

Why:
- The component used <X /> but never imported it.
- That would cause a compile/runtime error.

Other improvements:
- Created and exported a shared type:
  SelectedElementData

Why:
- Both ProjectPreview and Projects need to understand the selected element payload shape.
- Reusing one shared type reduces mistakes.

- Updated props typing for onUpdate so it matches the partial update flow.
- Changed handleChange to update top-level fields only:
  - className
  - text

Why:
- The previous logic was checking if field in values.styles and only then updating.
- That meant className updates would not flow correctly.
- The new version treats className/text as top-level fields and style fields separately.

- Kept handleStyleChange for nested style updates.
- Added a Text textarea so selected text content can also be updated.
- Cleaned the layout so the entire floating panel is contained in one positioned box.

Why this helped:
- The panel now works as a proper controlled editor for both content and styles.

5. Important connection details

Connection path after the fix:

Projects.tsx -> ProjectPreview
- passes callbacks for selection events
- holds the ref used to update the iframe

ProjectPreview -> iframe
- injects iframeScript
- listens to postMessage from iframe
- sends updates back with postMessage

Projects.tsx -> EditorPanel
- passes selectedElement
- passes onUpdate callback
- passes onClose callback

EditorPanel -> Projects.tsx
- sends update payloads when user edits form values

Projects.tsx -> ProjectPreview ref
- forwards those edits back to preview iframe

6. Why the panel was not opening before

Before the fix, the architecture had a broken middle layer:

- iframe side existed
- panel side existed
- page coordination did not exist

So the system had:
- click detection inside preview
- no React listener
- no selectedElement state
- no rendered editor panel

That is why it felt like "EditorPanel is not opening", but the real issue was "EditorPanel is not connected".
